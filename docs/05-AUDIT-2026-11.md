## 1. Synthèse

L'application est fonctionnellement riche, mais présentait trois familles de défauts graves :

1. **Fuites multi-tenant.** Plusieurs chemins (API REST, sync offline, filtres Filament) acceptaient des identifiants appartenant à un autre commerce. Un utilisateur du commerce A pouvait par exemple remettre à zéro le stock d'un produit du commerce B.
2. **Incohérences comptables.** Le stock, la dette fournisseur (`supplier.balance`) et la dette client (`customer.balance`) divergeaient dans des cas courants :
   - achat créé directement « validé » ;
   - annulation d'un achat en attente ;
   - suppression d'un paiement ;
   - modification d'un crédit ;
   - renvoi d'une opération de sync.
3. **Fonctionnalités cassées en production.** Plusieurs endpoints mobiles échouaient systématiquement :
   - violations NOT NULL ;
   - mauvaise signature de méthode ;
   - pages du module Portefeuille en erreur 500.

Point de risque supplémentaire : `phpunit.xml` faisait tourner les tests sur la **base MySQL de développement**. Un test utilisant `RefreshDatabase` l'aurait vidée. C'est corrigé : les tests utilisent maintenant SQLite en mémoire.

### Vérification

- **28 tests automatisés** (97 assertions) ajoutés : `php artisan test`, tous au vert. Ils couvrent :
  - l'API ;
  - la sync ;
  - le cycle de vie des achats ;
  - les crédits ;
  - le chargement réel des pages Filament Admin et Commerce.
- `migrate:fresh` et tous les seeders validés sur une base SQLite jetable.
- Les smoke tests Filament ont détecté 3 crashs supplémentaires, corrigés avant livraison (constats S01–S03).

### 2.1 API mobile & synchronisation

| ID | Sév. | Constat | Statut |
|---|---|---|---|

## 3. Actions requises après déploiement

1. **Migrations** : `php artisan migrate`. Ajoute `sync_operations`, `shops.subscription_expires_at`, l'unique `wallets.shop_id`, ainsi que la migration `wallets.status` qui était en attente.
2. **Rôles** : `php artisan shield:generate --all` puis `php artisan db:seed --class=ShopRolesSeeder`, pour donner `page_Caisse` au caissier et retirer les droits admin aux propriétaires.
   - ⚠️ Les rôles personnalisés existants (ex. « Propriétaire » en base locale) ne sont **pas** modifiés par ce seeder. Vérifie-les dans `/admin/shield/roles`.
3. **App mobile** `beez-mobile` : plusieurs comportements ont changé (permissions, totaux recalculés…). Voir [04-API.md § Notes de migration](04-API.md) → 📋 US-406.
4. **Fichiers non suivis** : `app/Enums/`, la migration `2026_07_15_120005` et la `WalletResource` Commerce ne sont pas encore dans git. Sans eux, un clone frais est cassé.
